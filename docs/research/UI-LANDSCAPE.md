# UI landscape research

Inputs to the design system in [BRAND.md](../BRAND.md). Reviewed 2026-07-30,
focused on how currently-funded developer-tool companies (YC and a16z
portfolios) present themselves, and which of those patterns survive contact
with an open-source CLI/MCP project that has no sales funnel.

## Findings

**1. The dark developer hero is now table stakes, not a differentiator.**
The aesthetic — near-black background, cool gradient, monospace accents —
became the category default precisely because it signalled technical
credibility, and is now saturated enough that it no longer distinguishes
anything. The consensus in that discussion was blunt: visual treatment is not
where differentiation happens any more; the value proposition copy is.

**2. Differentiate on the single claim competitors cannot honestly make.**
The recommended exercise is to name the one thing your tool does that its three
closest competitors cannot claim. For prompt2md that is not speed or format
coverage — those are commodity. It is that **compression is reversible and the
savings are auditable**: originals are stored before transformation, anchors
resolve to byte-exact source, and every number is reproducible from the repo.

**3. Warm colour in a cold category is a real differentiator.**
Supabase's green is cited as one of the most effective visual differentiators
in developer tooling, in a space converged on blue/violet. We applied the
principle to the *substrate* (warm ink + paper grain) rather than the accent,
because a warm accent would collide with the semantic warning colour and
because the fold/paper story makes warm paper tones meaningful rather than
arbitrary.

**4. Distinctive typography signals intentionality.**
The default stack (Inter, Geist, and similar neutral geometric sans) reads as
"competent"; a deliberate typeface choice reads as designed. Hence a serif
display face, used sparingly.

**5. Show the product immediately.**
The highest-converting pages lead with real interface, screenshots, or an
embedded demo in the first or second scroll rather than aspirational copy. Our
advantage: the studio *is* the product, so it is the landing page. No marketing
shell in front of it.

**6. Specific quantified claims beat aspirational language,** and transparent
numbers function as a trust signal for technical audiences. Aligned with the
project's existing rule that reported savings come from real reports, never
from prose.

**7. The strongest possible demonstration is a product used to build its own
site** (Framer built in Framer, Webflow in Webflow). prompt2md's equivalent:
the Daily Digest is generated by our own pipeline every day and archived with
its real token ledger, and the docs corpus runs through the same conversion
path the product sells.

**8. Restraint in navigation.** Fewer than five nav links, a single primary CTA,
no competing actions above the fold. Linear is repeatedly cited as the
reference for "each page communicates a single idea".

**9. Performance is a credibility signal.** Sub-two-second loads read as
technical competence. Our studio ships no UI framework beyond React, no icon
library, no webfont network fetch, and no analytics.

## Deliberately not adopted

- **Bento grids everywhere / glassmorphism / 3D device mockups** — currently
  fashionable, but decorative here. We use a bento arrangement only for the
  stat tiles, where the varying tile weight carries real meaning (the savings
  tile is the claim).
- **Neo-brutalism** — floated in the same discussion as the "next" look after
  dark heroes. It fights legibility for dense numeric output.
- **Scroll-triggered animation** — the studio is a workbench, not a scroll
  narrative; motion is reserved for explaining value changes.
- **Customer logo walls** — the single highest-cited proof element, and one we
  cannot honestly use. An open-source project pre-launch has no customers, and
  fabricating or implying them would violate the project's own reporting rules.
